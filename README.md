This repository holds the website for
[Jinnie](https://github.com/newmachinesph/jinnie), an offline-first personal
finance super app for the Philippines. It also holds **Jinnie Learn**, a free,
bilingual (English/Filipino) financial-literacy course that runs from age seven
to retirement.

- **[jinnie.ph](https://jinnie.ph):** the marketing site, a page for each mini
  app, the developer SDK guide, and security and legal pages
- **[learn.jinnie.ph](https://learn.jinnie.ph):** 6 learning paths, 48 lessons,
  255 learning bites, 16 scam drills, and a glossary, with Philippine narration
  and localized videos. It works offline and opens inside the native app

Built with Next.js 16 (App Router, Turbopack), React 19, and Tailwind v4. There
is no CMS and no database. Authored content stays in this repo. Learning
progress stays in browser storage or in the native app's bridge.

## Run

Requires Node.js 22+ and pnpm 11.

```powershell
pnpm install
npm --prefix learn ci   # course tooling has its own dependencies
pnpm dev --port 3010  # marketing: localhost:3010; course: learn.localhost:3010
pnpm build           # publishes media + builds Next; `pnpm start` serves it
pnpm lint
pnpm test:learn       # course tests and content lint
pnpm check:learn      # validate generated course and media
pnpm check:learn:routing -- http://localhost:3010  # check host routing on a running server
```

## Configure

Every variable is optional. To override a default, set it in `.env.local` or in
your hosting provider's environment.

| Variable | Used for |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `metadataBase`, canonical URLs, sitemap, robots |
| `NEXT_PUBLIC_CONTACT_EMAIL` | Every `mailto:` on the site |
| `NEXT_PUBLIC_LEGAL_ENTITY` | Copyright line and the legal pages |

Defaults live in `src/lib/site.ts`.

`JINNIE_ASSET_ORIGIN` points generated Learn media and screenshots at a CDN
(`https://cdn.jinnie.ph` in production). Leave it unset to serve the local
files.

## Website analytics

The shared root layout loads Google Analytics `G-FMBT4CHHBW` through
`@next/third-parties/google` in production builds. This covers both `jinnie.ph`
and `learn.jinnie.ph`, including hosted Learn inside the Android WebView.
Development mode does not load the tag. No custom events export financial
records, learning progress, or practice answers.

In GA4, keep Enhanced Measurement > Page views > Page changes based on browser
history events enabled for Next.js client-side navigation. The tag is mounted
once at the root; do not add duplicate tags or manual page-view events in the
site or Learn layouts. See the
[Next.js integration guide](https://nextjs.org/docs/app/guides/third-party-libraries#tracking-pageviews).

## Phone mockups

The app is still in development, so the site shows no screenshots. Instead,
`src/components/PhoneFrame.tsx` draws a phone frame around a schematic of each
screen: masked figures, skeleton rows, the real app bar and tab bar. Pass
`screen="home"`, `"launcher"`, or any app id from `src/lib/apps.ts`. The
screen is laid out at 360×780 and scaled to the frame width, so one component
serves the 200px thumbnails and the 280px hero phone. Swap the schematic for a
real capture once the app is ready to be shown.

## Design

Tokens in `src/app/globals.css` mirror `packages/sdk/src/theme.ts` in the app
repo: indigo primary, night surfaces for totals, one lamp-gold accent, green
and red only for money in and out. System fonts and tabular numerals keep the
site lightweight. Marketing typography, cards, navigation, and responsive
composition are scoped in `src/app/site-polish.css`; Learn owns
`src/app/learn/learn.css`. Dark mode follows the system.

## Learn: one source

The Next page at `src/app/learn/[[...segments]]/page.tsx` validates route/content
IDs and renders the React screens in `src/components/learn/`. The Learn layout
owns its navigation, error boundary, progress hydration, and native bridge.
Marketing pages are grouped separately in `src/app/(site)/`, with their own
header/footer and unchanged public URLs.

`learn/` is the only authoring source for lessons, translations, shared learning
logic, illustrations, narration, videos, and tests. Next imports the content
and shared modules directly. Development publishes media on startup and watches
media files while Next handles source updates; production validates `public/learn-assets/` before compiling
Next. The generated media directory is ignored by Git; do not edit it or copy
it into Expo. No standalone course HTML or source-script directory is served.

Both `jinnie.ph` and `learn.jinnie.ph` use this same deployment. The Learn host
maps its real routes to the internal `/learn` application through `src/proxy.ts`.
Local `/learn` works without public DNS. The Expo app opens
`https://learn.jinnie.ph/?embed=native` in a WebView, so the course is the top
document and the native bridge can reach it directly. There is no website
iframe wrapper and no separate native course bundle to release or synchronize.

Browser course progress stays local to the Learn origin. Native progress is
stored by the app's bridge and participates in its Settings backup and reset.
Learn's own export/import controls remain available to move learning backups.
Opening Learn in an ordinary browser does not expose the native finance bridge.

The generated `public/learn-assets/integration-manifest.json` records the
asset build and file hashes. `/learn-sw.js` handles production offline support,
scoped to the Learn application. Previous `/learn-content/index.html` links
redirect to the Next app; other retired static paths return 404.
See [Learn host routing](docs/learn-hosting.md) for
local checks, offline scope, and domain setup. DNS and deployment are separate
external steps; the code does not publish them automatically.
